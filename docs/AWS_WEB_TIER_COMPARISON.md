# Web tier: Lambda Web Adapter (LWA) vs custom Amplify deployment bundle (2026-11-22)

**Both paths are preserved. Neither is approved or deployed.** "Local pass" below means CPU-only tests on this laptop; it is **never** evidence of real AWS behaviour.

| Dimension | A. LWA + Function URL (+CloudFront) | B. Amplify Hosting + custom deployment spec |
|---|---|---|
| What AWS documents | Lambda/Function URL are generic; LWA is an AWS Labs project (not an Amplify feature). Nothing is version-gated to Next.js 12–15. | **Managed** SSR documented for Next.js **12–15** only; Next.js 16 absent from three official pages (checked twice today). The *deployment specification* is generic ("Node server on :3000"), so a custom bundle is permitted but unsupported-by-name for 16. |
| Repo artifact | `scripts/validate_nextjs_lambda.py`; standalone zip 22.8 MB, 0 native binaries (ARM64/x86 safe). **No web-tier IaC exists** (`infra/aws/template.yaml` defines the API Lambda only; docs list the web Lambda as "not yet drafted"). | `scripts/build_amplify_bundle.py` + `infra/aws/amplify.yml`; bundle 22.8 MB (limit 220 MB). Needs no IaC beyond an Amplify app + branch (console/CLI), but see blockers. |
| Local evidence | 0 failures: SSR, static immutability, redirects stay on public origin, `no-store` on auth, CSRF incl. X-Forwarded-Host spoofing, multiple `Set-Cookie`, 120 MB RSS. | 20/20 spec checks incl. no symlinks/.env/maps, entry on :3000, SSR 200, static fallback; `.env.production` is read at runtime (redirect used the configured origin); sign-in CSRF 403, BFF 401. |
| NOT proven locally | Real LWA layer, Function-URL payload v2 translation (cookies array), CloudFront Host handling, cold start, 6 MB buffered-response limit. | Everything Amplify-side: compute runtime for Next 16, `proxy.ts`, `Set-Cookie`/redirect rewriting by Amplify's router, cold start, how `.env.production` is placed, build image has python3.13 (unverified), `appRoot`-relative `../../scripts` path. |
| Streaming | Function URL supports `RESPONSE_STREAM`; **unneeded** (BFF buffers, browser polls). | Documented as **unsupported** for managed Next.js; unknown for custom compute; also unneeded. |
| Security | No third-party Git integration; artifact built locally and uploaded (S3 → Lambda). Function URL `NONE` is public at the edge: app auth + CSRF + Host checks are the control (tested). Needs CloudFront OAC/secret header to stop bypass of CDN (not drafted). IAM: existing deployer policy covers lambda/cloudfront/s3/cloudformation. | Git-connected builds need the **Amplify GitHub App on the private org repo** (new third-party access to proprietary source + webhook ⇒ every push becomes a billable build). Service role (IAM) needed. **`enigma-deployer` policy has no `amplify:*`** → AccessDenied until widened (review required). Build runs in AWS with env vars as build-time inputs (public ids only by design). |
| Ops complexity | Higher IaC/packaging work (layer, function, URL, CloudFront, OAC, cache/forwarding policies) but all explicit and testable offline. | Lower infra surface, but opaque managed router/compute; debugging needs SSR logs enabled; build image/Node/Python pinned via console settings; 220 MB / 15 min / 512 MB-tmp limits. |
| Cost (LIST, us-east-1, web tier only; `scripts/aws_cost_model.py`) | low **0.15** / moderate **1.07** / high **4.40** USD/mo (Lambda + CloudFront transfer/requests) | low **1.03** / moderate **2.48** / high **7.60** (SSR req+duration, $0.15/GB transfer, 20 builds×4 min assumed, storage). Memory/build counts are assumptions; free columns not applied (account applicability UNKNOWN). |
| Full stack, Track B + Cognito Lite + logs (list) | 0.37 / 2.40 / 7.44 USD/mo | 1.26 / 3.87 / 10.80 USD/mo |
| Unbounded exposure | Lambda reserved concurrency 5 caps parallelism; Function URL abuse still billable (WAF not planned). | Amplify has no documented concurrency cap for SSR; data transfer $0.15/GB; abuse is billable; WAF $15/mo option not planned. |
| Live tests required | LWA layer + Function URL: SSR, login callbacks, cookies/redirects behind CloudFront, CSRF with real Host, 401/403 matrix, two-tenant isolation via real Cognito, polling chat to Kaggle, log retention, teardown. | Same matrix **plus**: does Amplify compute accept the bundle at all; Next 16 `proxy.ts`; env placement; GitHub-app trigger behaviour; build minutes. |

## Reading of the evidence
- B's only advantage is fewer moving parts *if* Amplify runs Next.js 16 — which AWS does not say it does. A has no version gate but has **more unwritten IaC** and a CloudFront bypass item.
- A is cheaper on every modelled workload (by ~$0.9–$3.4/mo) and avoids new Git access to the private repo. Neither is a $0 guarantee.
- Recommendation (not a decision): prefer **A** for the first approved live test because it needs no GitHub app and no policy widening; keep B for a later, separately approved experiment.
